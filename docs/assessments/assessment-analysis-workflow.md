# Assessment Analysis Workflow — Agentic-Only Folder Pattern

Status: implemented — staging script (`scripts/stage_assessment.py`, self-tested) and
`assessment-analysis` skill (`/assessment-analysis`) exist; operator smoke runs with real
exports remain (see Validation).

## Purpose

Analyze assessment run exports (a mix of json, md, csv, and xlsx files) with a
local model, produce recommendation drafts that operators review, and feed the approved
findings into technical and quarterly meetings — with no provider connectivity and no
credit cost (no Cowork/Copilot dependence).

## Why the "agentic-only folder" pattern

Assessment exports are messy: many files, mixed formats, generated by different tools.
Dumping the whole export into an agent's workspace wastes context, invites hallucinated
reads of stale files, and widens the permission surface. Instead, a staging step curates
exactly what the agent may see — the agentic-only folder — so:

- the model works from a manifest, not from directory spelunking,
- large CSVs are pre-aggregated or capped instead of overflowing context,
- permissions can scope to one run folder, and
- operators can inspect what the agent had access to (reviewability).

## Workflow

```
assessment/
  <run-id>/
    input/                  # staged, curated (the agentic-only folder)
      manifest.json         # file list: name, format, rows/entries, size, notes
      findings.json         # (optional) normalized source data, sized to context
      notes.md              # operator notes, previous-run context
      *.csv / *.json / *.md # curated export files (xlsx converted to csv in staging)
    output/                 # agent writes here; nothing else is writable
      recommendations.md    # draft, requires operator review
      summary.xlsx          # optional, via xlsx-workflow skill
```

### 1. Stage (operator or script)

- Copy the run export into `assessment/<run-id>/input/`.
- Normalize: strip binaries, dedupe, cap oversized files (e.g. split >1MB CSVs into
  aggregates or row-sampled views), convert non-utf8 encodings.
- Convert Excel (`*.xlsx`) inputs to csv during staging (pandas/openpyxl) so the agent
  reads a single uniform format; keep a `notes.md` entry recording the conversion. Only
  leave xlsx files for the agent to open if the sheet layout is trivial.
- Generate `manifest.json` listing every staged file with format, record counts, and
  truncation notes. The manifest is the agent's index of truth.

### 2. Analyze (local agent, OpenCode)

- Start the runtime: `./bin/lac runtime start`, then launch OpenCode in the
  `assessment/<run-id>` workspace with the privacy-locked config below.
- Prompt contract (to be baked into the skill in the follow-up phase):
  - Read `manifest.json` first; analyze only files listed there.
  - Prefer `bash` + python/pandas for any file too large to read fully.
  - Write `output/recommendations.md` with fixed sections:
    - Summary (3-5 bullets)
    - Findings — each with a reference to the source file (and row where applicable)
    - Recommendations — ranked, each with rationale and required action
    - Data gaps — files/fields that were missing, capped, or unusable
    - Confidence — per-finding low/medium/high
  - Never invent numbers: every figure must trace to a file in the manifest; if a
    figure cannot be traced, list it under Data gaps.

### 3. Review (operator gate)

- Operator reads `recommendations.md`, corrects or approves.
- Approved content is the source for technical and quarterly meeting material
  (markdown for meetings; optional deck via the pptx-workflow skill).
- The agent's output is always a draft until an operator approves it — the model
  never writes directly to meeting channels.

## Model and harness selection

From `agentic-model-review.md` and `agentic-harness-review.md`:

- Harness: OpenCode (keep; OpenChamber only if a browser UI is needed).
- 32 GB workstation: Qwen 3.6 27B Q4 (mid tier — recommended default).
- 16 GB portable: Gemma 4 12B (small tier — assisted analysis, expect steering).
- 128 GB M4 Max: Qwen 3.6 35B-A3B Q8 (high tier — headroom for long exports).
- E4B/2B and sub-Q4 quants are non-agentic; do not use them for this workflow.

## Permissions (privacy-locked workspace config)

Open the run folder as the OpenCode workspace and scope permissions to it:

```jsonc
// assessment/<run-id>/.opencode/opencode.json
{
  "permission": {
    "edit": "allow",        // only files under this workspace
    "bash": "allow",        // python/pandas for large CSVs
    "webfetch": "deny"      // no network: privacy + prompt-injection safety
  }
}
```

The model endpoint is the local `llama-server` on `127.0.0.1`; with `webfetch` denied
there is no channel for data to leave the machine.

## Error handling

| Failure | Mitigation |
|---|---|
| Context overflow on a large export | Re-stage: split/cap files, pre-aggregate in the staging step, rerun |
| Tool-call failure (model emits invalid call) | Retry once; if repeated, reduce task scope (analyze one file or section) |
| Empty manifest (staged folder has no files) | Agent reports the run as unanalyzable and exits; staging is at fault, not the model |
| File listed in manifest but missing | Agent reports it under Data gaps; never guesses contents |
| Model invents figures | Output contract demands source refs; operator review gate catches the rest |
| Operator has no terminal | Use OpenChamber against the same runtime (UI path) |
